# سجل الإشراف — مدرسة الأصمعي

موقع لطاقم الإشراف: الطلاب، والتعهدات والتقارير والاستدعاءات والفصل، وملف لكل طالب، وإشعارات. يعمل على الجوال ويُثبَّت على الشاشة الرئيسية مثل التطبيق.

- **الموقع:** ملفات ثابتة في مجلد `site/` تُنشر على GitHub Pages.
- **قاعدة البيانات وتسجيل الدخول:** Supabase (الخطة المجانية).
- **النشر:** تلقائي مع كل تحديث على الفرع `main` عبر `.github/workflows/deploy.yml`.

## محتويات المستودع

| المسار | ما فيه |
|---|---|
| `site/index.html` | هيكل الصفحة والأيقونات |
| `site/css/app.css` | الألوان والخطوط والتصميم (المتغيرات في أول الملف) |
| `site/js/config.js` | رابط مشروع Supabase ومفتاحه العام |
| `site/js/api.js` | كل التعامل مع قاعدة البيانات |
| `site/js/core.js` | أنواع الإجراءات والحالات والأدوار، والإشعارات، والتنقل |
| `site/js/views.js` | الشاشات: الرئيسية، السجل، الطلاب، ملف الطالب، الإشعارات، المزيد |
| `site/js/sheets.js` | الدخول، والنوافذ السفلية (تسجيل إجراء، القيد، الطلاب، الاستيراد، الحسابات) |
| `site/sw.js` و`site/manifest.webmanifest` | تثبيت الموقع كتطبيق والعمل دون اتصال |
| `supabase/migrations/` | جداول قاعدة البيانات وقواعد الحماية، ملف جديد لكل تعديل |
| `supabase/functions/staff` | وظيفة الخادم: إعداد المسؤول الأول، وإضافة حسابات الطاقم وتعديلها وإيقافها وتغيير كلمات السر |

## الإعداد لأول مرة

1. **GitHub:** مستودع عام (Public) باسم `asmaei-ishraf`.
2. **Supabase:** مشروع جديد. احفظ كلمة سر قاعدة البيانات.
3. **المفاتيح السرية في GitHub:** من إعدادات المستودع ← Secrets and variables ← Actions ← New repository secret:
   - `SUPABASE_ACCESS_TOKEN`: من supabase.com ← حسابك ← Access Tokens ← Generate new token
   - `SUPABASE_DB_PASSWORD`: كلمة سر قاعدة البيانات
   - `SUPABASE_PROJECT_ID`: الجزء الذي يسبق `.supabase.co` في رابط المشروع
4. **GitHub Pages:** إعدادات المستودع ← Pages ← Source: **GitHub Actions**.
5. **الربط:** ضع رابط المشروع والمفتاح العام (Publishable أو anon) في `site/js/config.js`.
6. عدّل رابط المشروع أيضاً في سياسة الأمان داخل `site/index.html` (السطر `connect-src`).
7. أول تحديث على `main` ينشئ قاعدة البيانات والوظائف وينشر الموقع.
8. أنشئ رمز إعداد لمرة واحدة من محرر SQL في Supabase:
   `insert into public.app_secrets (key, value) values ('setup_code', 'رمز-عشوائي-طويل');`
9. افتح الموقع وأنشئ حساب المسؤول من شاشة «إعداد السجل لأول مرة» باستخدام الرمز.

## التحديث والتطوير

- كل تحديث على الفرع `main` يُنشر تلقائياً خلال دقائق، وتظهر حالة النشر في تبويب **Actions**.
- **تعديل قاعدة البيانات:** أضف ملفاً جديداً في `supabase/migrations/` باسم يبدأ بتاريخ أحدث، ولا تعدّل ملفاً نُشر من قبل.
- **الأدوار والصلاحيات:** القوائم في `site/js/core.js` (`APPROVERS`, `OVERSEERS`, `MANAGERS`) ويقابلها في قاعدة البيانات `approver_roles()` و`overseer_roles()` و`manager_roles()`. عدّل الاثنين معاً.
- **إضافة نوع إجراء أو مخالفة:** `TYPES` و`STATUS` و`VIOLATIONS` في `core.js`، ونوع الإجراء أيضاً في قيد `type` بجدول `actions`.

## الأدوار

| الدور | الصلاحيات |
|---|---|
| مشرف | يسجل الإجراءات، يرسل طلب الفصل للاعتماد، يحذف قيوده فقط |
| المشرف العام، الوكيل، المدير | يعتمدون الفصل ويرفضونه، يرون كل التقارير، يصحّحون ويحذفون أي قيد، يديرون الطلاب |
| شؤون الطلبة | تدير قوائم الطلاب وتستقبل التقارير الموجهة إليها |
| مسؤول الموقع (خيار مستقل عن الدور) | يضيف حسابات الطاقم ويعدّلها ويوقفها ويعيّن كلمات السر |

## الأمان

- **لا يرى البيانات إلا الطاقم:** قواعد الحماية (RLS) في قاعدة البيانات تمنع أي شخص غير مسجل أو حساب موقوف من قراءة أو كتابة أي شيء، حتى لو حصل على رابط الموقع أو الكود.
- **الدوال المساعدة في مخطط خاص (`private`)** لا يمكن استدعاؤه من الإنترنت.
- **الصلاحيات تُفرض في قاعدة البيانات:** تسجيل الإجراءات وتغيير حالاتها يتم عبر دوال تتحقق من الدور (`create_action`، `move_action`، `resched_action`)، فما يقدر المشرف يعتمد الفصل حتى لو عدّل الصفحة في متصفحه.
- **لا يوجد تسجيل ذاتي:** الحسابات ينشئها مسؤول الموقع فقط عبر وظيفة `staff`. أغلق خيار Allow new users to sign up في إعدادات Supabase ← Authentication.
- **إعداد المسؤول الأول برمز لمرة واحدة** محفوظ في `app_secrets`، ويُحذف بعد الاستخدام.
- **سجل لا يُمحى:** سير كل قيد (`action_log`) لا يُعدَّل من المتصفح، وكل حذف لقيد أو طالب يُحفظ في `deleted_log` مع اسم من حذفه، ويراه مسؤول الموقع.
- **كلمات السر:** 8 أحرف على الأقل، والحساب الموقوف لا يقدر يدخل.
- **سياسة أمان المحتوى (CSP)** في `index.html`: لا يُحمَّل كود إلا من الموقع نفسه، ولا يتصل إلا بمشروع Supabase. إذا تغيّر رابط المشروع فعدّله هناك وفي `config.js`.
- **فحص دوري:** شغّل Security Advisor في لوحة Supabase بعد أي تعديل على قاعدة البيانات.

## ملاحظات

- اسم المستخدم يتحول داخلياً إلى بريد وهمي `اسم@staff.asmaei.invalid` لا يُرسل إليه شيء. القيمة نفسها في `site/js/config.js` و`supabase/functions/staff/index.ts`.
- الخطة المجانية في Supabase قد توقف المشروع مؤقتاً إذا لم يُستخدم فترة طويلة (مثل العطلة الصيفية). تعيد تشغيله من لوحة Supabase بزر **Restore**، والبيانات تبقى.
- المفتاح العام في `config.js` آمن في المتصفح. لا تضع المفتاح السري (secret / service_role) أو كلمة سر قاعدة البيانات في أي ملف.
